# 本地链样例与测试

本指南对应 `contracts/scripts/seed-local.ts`。所有数据通过真实合约交易产生，只允许在 Chain ID 31337 上运行，不会往 Sepolia 造样例。

## 运行方法

在项目根目录的第一个终端启动并保持节点运行：

```bash
npm run node --prefix contracts
```

第二个终端执行：

```bash
npm run build --prefix contracts && npm run seed:local --prefix contracts && npm run export-interface --prefix contracts && npm run dev --prefix frontend
```

前端开发者菜单切到本地链，MetaMask 也使用 Hardhat Local。`frontend/.env` 的 `VITE_LOCAL_MARKET_ADDRESS` 留空，或与本次输出地址一致。前端未启动时不会自动打开预览。

脚本新部署一个合约，不删除旧合约。同一节点中再次执行会拒绝，不重复登记或消耗测试资金。要从头生成，停止并重启 Hardhat，再重新执行生成和导出命令。若重启后 MetaMask 显示旧的交易 nonce，可在该本地测试账户的高级设置中清除活动和 nonce 数据。

## 建议逐项检查

1. 作者进入“个人挂单”：挂单应有 7 页、已签发许可 3 页、登记作品 3 页。每页 8 项；切换状态、搜索编号和翻页。
2. 切换第二作者：只能看到该作者的 6 件作品和 8 笔挂单，不能撤销主要作者的挂单。
3. 发现页切换五种类别，检查作品 #21 默认隐藏，开启“包含已撤销”后显示。检查英文名称、各自简介、对应类型的授权范围，以及带链接和无链接作品。
4. 打开作品 #1，顶部应有 #39、#53、#54 三笔常规可接受挂单，另有 #1 短接受窗口挂单，价格和期限各不相同。用不同买家分别接受 #53 和 #54，确认各自得到独立许可，#39 仍可接受；两位买家分别扣除 0.0005 ETH、0.002 ETH 及 Gas。作品 #25、#26 也可做相同测试。作者的有效许可及可领取余额随接单增加；同一笔挂单不能被重复接受。
5. 作者取消挂单 #40：锁定押金减少 0.0012 ETH，可领取余额增加同额，历史挂单保留为卖家取消。
6. 作者提前撤销许可 #15：先核对弹窗中的双方分账，再签名；许可失效，作者押金减少，双方待领取余额增加。
7. 在“使用权查询”用主要买家地址查询，能看到有效、作者提前撤销、登记被撤销等许可状态；等待真实到期后再检查到期状态。按作品编号查询。该页目前最多读取 50 条许可，本样例主要买家有 20 条。
8. 个人账户检查本人可领取余额及锁定押金；管理员进入管理台检查全平台金额和案件费用池。生成后主要作者锁定 0.0437 ETH、第二作者锁定 0.0106 ETH，全平台合计 0.0543 ETH。这些是刚生成时的金额，手动接单、取消或结算后会相应变化。
9. 作者生成后可领取余额是 0.0172 ETH，来自新接受许可收入及新取消挂单退款；不是重复退还同一笔押金。领取后钱包增加相应 ETH，同时扣除本次 Gas，合约可领取余额归零。

脚本保留短期挂单和许可，等待真实到期；部分登记失效样例未退款或未结算，便于检查“状态失效”和“资金已处理”是两回事。目前前端没有到期结算及失效挂单退款按钮；这些条目可用于读取和金额核对，不能在页面上完成这两类操作。

## 批量挂单与列表筛选

作者在“个人挂单”中为某件作品选择创建挂单，手动填写批量份数（1–20，默认 1）。价格、固定补偿和许可期限均为每份配置；总押金是 `(价格 + 补偿) × 份数`，另付一笔交易的 Gas。前端调用新增的 `createOffers`，一次请求 MetaMask 签名；整批全部成功或全部失败，各份挂单仍独立接单、撤销和结算。旧合约需重新部署，再导出新接口及地址；原有单份方法 `createOffer` 保留，本地样例数量和场景不变。

拒签时不创建任何挂单；交易执行失败时整批状态和押金回滚，但已上链的失败交易可能扣 Gas。回执超时后表单配置保持锁定，点击“检查交易结果”继续等待同一笔交易，不重复发送。关闭表单、离开页面或切换账户/网络不会取消已提交交易，应先核对钱包和链上结果，再决定是否发布新批次。

可以先发布 10 份同配置挂单，打开作品详情检查每页最多 8 条、前后翻页、按编号/范围搜索，以及价格和许可期限联合筛选。个人挂单及作品详情会继续读取超过合约每批 50 个编号限制的后续数据，每 10 秒刷新编号和挂单状态，避免新挂单在数量增加后消失。

首次访问默认英文；明确选择中文后会记住该浏览器的偏好。

## 交易权限和余额核验

MetaMask 是签名工具，不是合约权限中心。前端通过 MetaMask 请求用户签名，所以会弹确认框。脚本通过 Viem 发送 `eth_sendTransaction`，由 Hardhat 节点控制的、已解锁的测试账户签名；这些账户的私钥由本地节点持有，因此无需 MetaMask。配置文件里的地址本身不能签名，也不会赋予合约权限。

两种方式最终都产生签名交易，合约都按 `msg.sender` 检查作者、管理员等权限。脚本没有使用冒充账户、直接改存储或设置账户余额。Hardhat 初始赠送的测试 ETH 只存在于本地链。

每笔交易都等待成功回执，并累计转出值与真实 Gas。作者历史余额领取后，再生成新的收入/退款。脚本逐个断言：

```text
最终钱包余额 = 初始钱包余额 − 发送的 ETH + 领取的 ETH − Gas
合约 ETH 余额 = 锁定押金 + 全部用户待领取余额 + 案件费用池
```

生成结束时会写入 `contracts/deployments/31337.samples.json`，包含样例编号、状态、结算标记、五个账户前后余额、Gas、135 笔交易哈希及金额核验结果所需数据。该文件是本机运行报告，已加入 `.gitignore`，不包含私钥。

MetaMask 连接相同账户和本地网络后，读取到的余额与脚本一致；它不一定把脚本发起的交易补进自己的“活动”列表。Sepolia 部署则使用 `contracts/.env` 的测试私钥在本机签名，公共 RPC 不持有你的私钥，也不能仅凭地址转走资产。
