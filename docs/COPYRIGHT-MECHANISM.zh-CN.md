# Copyright Ark：版权管理机制详解

[English](COPYRIGHT-MECHANISM.md) | [简体中文](COPYRIGHT-MECHANISM.zh-CN.md) · [返回 README](../README.zh-CN.md)

平台的登记、授权、押金和案件处理规则由 `CopyrightMarket.sol` 实现。本文说明这些规则及对应的前端操作入口。原实施规划书保留了早期设计，其中部分功能与现版本不同。

## 1. 平台究竟管理什么

平台记录“某钱包对某文件提出权利声明”，以及该钱包向买家发出的有期限使用许可。登记时间、文件指纹、挂单条款、许可状态、案件结果和资金变动可以通过链上数据核验。

登记不证明登记人是真实作者，也不自动判定侵权。它不是 NFT、所有权转让、在线法庭、DRM 或原文件交付系统。作品展示所需的外部内容由登记人提供公开参考链接，平台不存原件、封面、证据全文或裁决全文。

业务集中在一个 `CopyrightMarket` 合约中，引用 OpenZeppelin 的所有权和重入保护组件；不需要部署一组互相转账的业务合约。

## 2. 角色与权限

| 角色 | 可以做什么 | 不能因这个角色自动获得什么 |
| --- | --- | --- |
| 未连接钱包的访问者 | 读取作品、挂单、许可、历史状态和公开链上数据 | 发起需要签名的交易 |
| 普通钱包 | 登记作品、购买他人挂单、提现自己的余额；通过合约触发公开结算或注资 | 修改他人作品或管理员名单 |
| 某作品登记人/卖家 | 为自己的有效登记挂单、取消有效未成交挂单、提前终止自己签发的有效许可 | 购买自己的挂单、无代价终止已成交许可 |
| 许可买家 | 持有自己钱包对应的许可、查询和领取应得退款 | 转让或转授权该许可 |
| 额外管理员 | 录入和处理案件，使用管理台 | 更改管理员名单、任意提取用户押金 |
| owner | 拥有管理员能力，并可通过 `setAdmins` 管理额外管理员 | 绕过资金规则领取其他用户的钱 |

角色可以重叠，但作者不能购买自己的挂单。前端作者和买家不需白名单；真实权限取决于交易的 `msg.sender`，不是页面显示的标签。

默认本地示例 owner 是 Hardhat `#0`。普通部署初始 owner 优先取 `INITIAL_ADMIN_ADDRESS`，其次取脚本配置的首个 admin，最后才取部署钱包。owner 可以和支付部署 Gas 的钱包不同。线上实际 owner 以该合约 `owner()` 为准。

`setAdmins(address[])` 仅 owner 可调用，替换整个额外管理员名单，最多输入 50 个地址；零地址被拒绝，重复地址去重，owner 不必出现在额外名单中也有管理权限。删除地址并同步可撤权，不改变其已有的作品、许可和收入。当前 owner 之外的管理员不能修改名单。

开发者菜单里的文本框和默认 JSON 仅是地址草稿。必须由 owner 签名并确认同步交易后才成为链上权限；恢复默认不撤销链上授权。跨电脑共享的是链上名单，不是浏览器草稿。所有权组件采用 `Ownable2Step`；转移需提名和接收两个步骤，前端未提供转移入口。继承接口还包含放弃所有权，当前实现没有禁用它；放弃后将失去 owner 专属的名单管理能力，不应把它当作普通管理员撤权操作。

## 3. 作品登记、文件与去重

1. 前端选择文件并在浏览器读取，计算 SHA-256。当前界面接受非空、最多 20 MiB 的 PNG/JPG/JPEG/WEBP/TXT/PDF/MP3/WAV/MP4 文件；这是前端格式限制，不是链上保存文件。
2. 钱包提交 `registerWork`，包含非零文件指纹、标题、简介、类别和可选参考链接，合约记录登记人、登记时间及作品编号。
3. 合约要求同一文件指纹最多有一个仍有效的登记。发现有效重复指纹时拒绝；这只识别相同字节文件，不识别改格式、裁剪、近似内容或抄袭。
4. 标题最多 96 个 UTF-8 字节，简介和使用范围最多 512 个 UTF-8 字节；汉字通常占 3 字节，不能把这些上限当作同数量汉字。参考链接链上最多 256 字节，允许空或小写 HTTP(S) 前缀；前端会进一步规范化 URL，但合约不访问目标网站。
5. 类别为图片、文本、音频、视频、其他。文件、权利声明和参考链接之间的真实性由登记人负责，合约无法证明上传选择确实发生过。

有效登记无直接编辑/删除接口。管理员依据案件撤销后释放该指纹的有效登记占用，任何钱包可重新登记相同指纹；新记录的 `previousWorkId` 指向最近旧记录。重新登记不证明新登记人更真实，也不迁移旧许可、旧收入或押金。旧历史始终保留。

参考链接和所有元数据都是公开链上数据，不要填带私密访问令牌的链接。原始文件只参与本机指纹计算，不上传 Cloudflare 或其他存储。

## 4. 挂单与多人购买

挂单不是转让版权，而是出售一份非独占、不可转让、不可转授权、有期限的使用许可。

设每份许可价格为 `P`，作者提前终止的固定补偿为 `C`，则每份作者押金为：

```text
D = P + C
批量总押金 = D × N
```

作者为有效作品设置价格、固定补偿、期限、接受截止时间及使用范围。当前前端输入 1–365 天的许可期限，挂单接受截止时间设为所读最新区块时间之后 24 小时。**接受截止时间**限制买家最晚何时购买；**许可期限**从成交时才开始计算，不从发布时开始。

合约底层允许期限 60 秒至 365 天，接受窗口为交易执行时间之后至少 60 秒、至多 30 天。`P` 和 `C` 各自必须在 1 wei 至 1 ETH 范围内。直接调用合约不必使用前端的整天限制，但仍受合约边界约束。

新增 `createOffers(..., quantity)` 限制 `N = 1–20`，一次交易准确支付 `D × N`。任意校验失败整批回滚，不存在一笔交易里只创建前几份的部分成功。原 `createOffer` 仍可创建单份，供现有脚本使用。

每份挂单有独立编号、条款哈希、押金和接单状态，所以：

- 同一作品可以同时有多个相同或不同条款的有效挂单。
- 多人可以各自接受不同挂单，分别持有非独占许可，不互相挤占许可有效性。
- 一笔挂单只接受一次。争抢同一笔挂单时按链上执行顺序决定，后到交易被拒绝；已经上链的失败交易仍可能耗 Gas。
- 作者本人不能接自己的单。批量创建不代表同一买家获得 N 份许可，也不是可无限复用的库存入口。

`termsHash` 绑定链 ID、合约地址、挂单编号、作品编号与指纹、卖家、价格、期限、补偿、截止时间、使用范围和条款版本。买家 `acceptOffer` 必须提交匹配的哈希并准确支付 `P`。批量中的每份因为编号不同，哈希也不同。

## 5. 未成交挂单的取消、到期和退款

作者可通过 `cancelOffer` 取消仍有效、未成交挂单，整份 `D` 从锁定押金转入作者 `claimable`。未成交没有买家，不发生违约补偿。取消记录不删除，也不能再次取消获得第二次退款。

接受窗口已到期或作品登记被撤销时，合约拒绝新接单。此时由任何钱包调用 `refundUnavailableOffer`，将该份未成交押金 `D` 记入原卖家，触发者不能截取资金。已成交挂单走许可结算，不可再作未成交退款。

挂单状态是从存储状态、链上时间和作品撤销时间派生的；已成交、卖家取消、已到期、作品已撤销不是同一种结果。登记在接受截止前撤销则归为登记失效；如果先过了接受截止时间再撤销，未成交挂单仍按到期处理。状态变为不可接受并不会自己执行转账或退款交易。

## 6. 接单时为什么作者能领取价格，押金却仍锁定

买家接受挂单时支付 `P`。同一笔交易执行：

1. 把挂单标记已成交，创建买家专属 `License`。
2. 记录开始时间 `S = block.timestamp`、结束时间 `F = S + T`，其中 `T` 是许可期限。
3. 将买家刚支付的 `P` 记入作者可领取余额。
4. 继续锁定作者原来存入的 `D = P + C`，作为退款与补偿担保。

这里有两笔来源不同的钱：买家的价格和作者的担保押金。接单后作者可领取的 `P` 不是退回作者押金；没有买家接单时，创建挂单本身不会产生这笔许可收入。

许可有效区间为 `[S, F)`，到 `F` 时已经无效，不需要“到期交易”才能停止授权。许可生效与资金结算是分开的。

## 7. 已成交许可的三种资金结果

### 7.1 作者主动提前终止

仅许可卖家可对尚未结算、仍在有效期内、且登记未被撤销的许可调用 `revokeLicense`。设已履约秒数为 `elapsed`：

```text
E = floor(P × elapsed / T)
从押金分给买家 = P − E + C
从押金分给作者 = E
两者合计 = P + C = D
```

交易一次完成许可终止和押金分账；没有“先撤销成功、等作者以后补钱”的欠款步骤。买家获得剩余价格退款加固定补偿。预览按读到的区块计算，最终交易可能稍晚执行，秒级分账有微小变化。

例：`P = 0.001 ETH`、`C = 0.0002 ETH`，7 天期限恰好履行一半，`E = 0.0005 ETH`：

| 项目 | 金额 |
| --- | --- |
| 作者发布时支付的担保押金 | 0.0012 ETH |
| 买家接单支付的价格，已记给作者 | 0.001 ETH |
| 提前终止时从押金记给买家 | 0.0007 ETH |
| 提前终止时从押金记给作者 | 0.0005 ETH |

上述不含 Gas，金额先进入各自的可领取余额。考虑原始押金支出后，作者净收益是 `E − C`；买家净支出是 `E − C`。固定补偿来自作者自己的担保资金，不是平台凭空生成。

### 7.2 正常到期

未发生更早登记撤销且期限已到时，任何钱包可调用 `settleLicense`，将全部 `D` 退入作者可领取余额。买家已支付并使用了完整许可，不再得到退款。

作者之前收到买家价格 `P`，现在只是拿回自己的担保押金；忽略 Gas 后最终净收入仍为 `P`，不是 `2P + C`。结算和提现晚于到期，不会延长授权。

### 7.3 管理员撤销作品登记

如果作品登记在许可到期前被管理员撤销，该许可随登记撤销立即失效；任何钱包可分别调用 `settleLicense`，将整份 `D = P + C` 记给买家，作者从这份押金获得 0。

管理员的撤销交易只改作品与案件，不遍历所有挂单和许可。因此失效会立即反映在查询结果中，但押金仍要逐份触发结算。即使在原定结束时间之后才结算，只要登记撤销先于结束时间，仍使用全额给买家的规则。

已经提前终止并结算的许可不能赔第二次；登记撤销前已经到期的许可仍走正常到期退作者。登记恰在许可结束时间撤销时，不满足“早于结束时间”，按正常到期处理。同一时间戳里的交易仍按实际执行顺序工作：作者先提前终止并结算则不再变更，登记先撤销则禁止作者再主动提前终止。

## 8. 余额、提现、Gas 和费用池

`claimable[address]` 是合约欠某地址、已经可以领取的余额。许可收入、未成交押金退款、许可结算和案件报酬都先记账，再由本人调用 `withdraw(recipient)` 实际转出 ETH。接口允许指定非零收款地址；当前前端使用当前钱包自己作为收款人。

锁定押金不属于可领取余额。自己的待领取余额也不等于钱包现有 ETH，不能在未提现时直接用于支付新的交易。提现只取本人额度，转账前清零记账并使用重入保护；失败回滚，不会无故丢失领取资格。

所有发送交易的钱包自行承担网络 Gas，包括调用公开退款/结算的触发者。预估阶段失败可能没有发交易；钱包拒签不会产生链上扣款；已经上链执行失败则可能扣 Gas，但业务状态和转入押金回滚。Gas 由网络收取，不流入平台费用池。

正常资金关系为：

```text
合约 ETH 余额 = 锁定押金 + 全部可领取余额 + 案件费用池 + 意外盈余
```

`pendingCaseRewards` 是待拨付报酬登记额，不代表合约另外持有这么多 ETH，不重复加入上式。`getAccounting` 显示各项资金；个人账户显示本人的押金及余额，全平台统计在管理台。

独立费用池是**同一个合约里单独记账的一部分 ETH**，不是另一个钱包、自动补款账户或第二个合约。任何钱包可调用 `fundRewardPool` 明确注资；当前前端在管理员页面提供固定 0.01 ETH 注资按钮。普通部署不自动注资，本地样例脚本会注资 0.01 ETH。普通直接转账入口被拒绝，不应向合约地址裸转 ETH 代替调用方法。强制转入的意外盈余不会自动分配给用户或费用池，当前没有提取该盈余的业务接口。

## 9. 案件、管理员报酬与信任边界

1. 管理员在链下收集材料，再 `openCase` 录入作品编号、唯一案件参考编号和非零证据哈希。编号允许 1–64 个大写字母、数字或连字符；同一作品同一时刻至多一个待处理案件。
2. 待处理只是标记，不冻结登记、交易或许可。
3. 管理员 `resolveCase` 提交维持或撤销、非零决定哈希和决定摘要。任何当前管理员都可处理，不要求是原录入人。合约记录真实处理钱包和当前区块时间，不接受倒填撤销日期。
4. 维持不改变登记有效性；撤销使该登记不可再交易，并按前述规则影响许可。历史记录不删除。
5. 每案报酬为部署时确定的 `gasSubsidy + reviewReward`。默认分别为 0.0001 和 0.00005 ETH，合计 0.00015 ETH；Gas 补贴是固定数额，不是按实际 Gas 报销。
6. 结案即登记待拨付资格，费用池为零也能结案。任何钱包之后可调用 `creditCaseReward(caseId)`，检查费用池足额并把固定金额记给该案 `resolvedBy`；触发者、后任管理员不能改收款人。
7. 报酬只能拨付一次，拨付成功后仍需实际收款人提现。费用池不足会阻止拨付，但不撤销案件结果，也不挪用买家退款或用户押金。

管理员能够错误裁决、偏袒或提交虚构案件，合约不能判断材料是否真实，也没有多人仲裁、投票、申诉或身份审核。管理员能力是明确的信任边界。代码没有给管理员随意改价格、替换买家、清空余额或取走任意押金的业务方法，但登记撤销本身会影响许可及补偿分配。

## 10. 状态、历史查询和分页

作品状态为有效或登记被撤销。挂单展示可接受、已成交、卖家取消、到期或作品撤销。许可展示有效、作者提前终止、登记撤销导致终止、到期；`settled` 则单独表示押金是否已结算。

历史查询 `isLicenseValidAt(id, at)` 使用开始/结束时间、作者撤销时间、登记撤销时间判断指定时刻是否有效，不能查询未来。今天已撤销的许可，在撤销前的历史时刻仍可能有效；资金是否结算不改变过去的许可记录。

当前查询页 `/verify` 先取买家前 50 份许可，再按作品/时间过滤；超出部分不显示，不表示链上不存在。合约各类编号索引支持 offset 分页，每次最多 50 项。个人挂单和作品详情使用紧凑列表与每页 8 项筛选分页；它们和查询页不是同一条读取实现。合约事件及交易记录保留审计线索，MetaMask 活动列表不保证收录脚本交易或每笔合约内部到账。

## 11. 合约已有能力与当前前端入口

| 行为 | 合约方法 | 当前前端 |
| --- | --- | --- |
| 作品登记 | `registerWork` | `/register` |
| 单份/批量挂单 | `createOffer` / `createOffers` | `/offers` 使用批量方法，数量可为 1 |
| 取消仍开放的挂单 | `cancelOffer` | `/offers` |
| 未成交挂单到期/登记失效退款 | `refundUnavailableOffer` | **暂无按钮** |
| 买家接单 | `acceptOffer` | 作品详情的可接受挂单 |
| 作者提前终止及分账 | `revokeLicense` | `/offers`，有预览 |
| 到期/登记失效许可结算 | `settleLicense` | **暂无按钮** |
| 自己的余额提现 | `withdraw` | `/account` |
| 管理员完整名单同步 | `setAdmins` | `/dev`，owner 签名 |
| 案件录入及处理 | `openCase` / `resolveCase` | `/admin` |
| 费用池注资 | `fundRewardPool` | `/admin`，当前按钮固定 0.01 ETH |
| 案件报酬拨付到可领取余额 | `creditCaseReward` | **暂无按钮** |

调用暂无界面的方法，需要用该网络和新合约地址的脚本或合约工具，传入对应 offer/license/case 编号并支付调用者的 Gas。它们不会因为浏览器刷新或时间流逝就自动执行。README 的主要流程优先演示已有前端入口，不承诺这些按钮存在。

## 12. 本地、Sepolia 与部署边界

本机访问的前端允许切换 Hardhat 与 Sepolia；远程托管前端固定 Sepolia。网络选择改变数据来源和交易目标，不改变钱包权限，也不迁移数据。Cloudflare 不维护本地节点状态。

本地 `seed:local` 使用节点控制的测试账户签名，产生真实本地交易；它不使用 MetaMask、不冒充账户、不直接改存储，也不推进时间。Hardhat 重启丢失内存状态，需要重建示例并导出；固定测试私钥只是让账户地址可重复，不意味着链上状态也保留。

部署不使用可升级代理。新版合约必须重新部署到新地址，旧合约数据和资金仍保留在旧地址。前端与 Cloudflare 的公开地址配置只选择读取哪个实例，不会帮用户搬迁资金或复制管理员权限。
